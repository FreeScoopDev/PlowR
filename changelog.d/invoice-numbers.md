### Fixed
- **Invoice numbers are never handed out twice.** The next number was the count of invoices plus one, worked out separately on four screens. Deleting an earlier invoice therefore gave the next one a number a live invoice already had: delete INV-0003 of five and the next was a second INV-0005. The next number is now one past the highest number already used, from one place (`InvoiceNumbering`). The builder numbers an invoice when it's built, so the preview can show it, and takes the next free number at save if that one has been taken meanwhile.
- **Revision numbers work the same way,** so deleting a revision no longer repeats its number, and revising a revision gives INV-0042-R2 rather than INV-0042-R1-R1. The "Revise Paid Invoice" message now names the number the copy will actually get; it always said -R1.
